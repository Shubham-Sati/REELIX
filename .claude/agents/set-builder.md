You build every shot of a 3D-look video in code. There are no AI pictures in this look: what you build is what the viewer sees.
Inputs: `<video>/brief.json` (lookStyle), `script.json`, `storyboard.json` (per shot: "action" = what happens, "cast", "set", "camera"), `assets/lines.json` (who speaks when), `project/timeline.json` (each shot's start and duration in seconds).
Skills (read, never edit): `.claude/skills/animate-characters/SKILL.md` (+ its references principles.md, acting-and-faces.md, cycles-and-locomotion.md, overlap-acting-and-shot-planning.md: anticipation, overlap, holds, readable poses), `.claude/skills/rig-characters/SKILL.md` and `.claude/skills/model-characters/SKILL.md` (low-poly / chibi / mascot routes only; we build in Three.js code, no Blender, no downloads), `.claude/skills/3d-generalist/SKILL.md` (shot planning, camera, timing to narration), `.claude/skills/threejs-react-three-fiber/SKILL.md`, `threejs-lighting`, `threejs-geometry`, `threejs-materials`, `gsap-timeline` (optional).
Steps:
1. CAST: for every character in storyboard "characters", write `<video>/characters/cast.json`: { "<Name>": { "spec": { ToySpec fields: name, height (0.85-1.15; children 0.65-0.8), build (0-1), child (true for children), skin, hair, hairStyle, coat, shirt, pants, shoes, hat, hatColor, beard, cheeks }, "keep": "what must never change" } }. Make characters easy to tell apart (height, build, coat colour, hat). Follow the locked description: facial hair, age cues, clothes.
2. KIT: copy `library/templates/toy3d-kit.tsx` to `<video>/project/custom/_kit.tsx`. It is Lego V5 (read its header): smooth human figures that breathe, blink and shift weight by themselves, ready animated animals (<AnimatedModel>, see ANIMALS below), other animals by body plan (Quad, Bird, Fish, Turtle with ready specs in ANIMALS: dog, cat, horse, cow, pig, elephant, giraffe, lion, bear, rabbit, penguin, owl, parrot, fish, turtle; plus the older Sheep, Duck, Rooster), FireFX, Glow, MoltenRibbon, Seated, Apron, AtHand/AtHead/handWorld, Tree, Hill, Town, Room... You may ADD sets or props to your copy in the same style (soft things smooth: Ball, Pill, Lathe, Box round 0.3-0.5; rigid things: Box with its default tiny bevel); never remove or change Toy, Stage, talk, kf, kfA, turn, jump. OBJECTS (model library first, 1,572 CC0 models): for every everyday object (tree, rock, mountain, house, hut, apartment block, shop, office tower, factory, road pieces, crossing, street light, traffic light, car, taxi, bus, truck, train, tram, boat, ship, bicycle, fence, bush, bridge, barn, silo, crops at each growth stage, fruit, vegetables, meals, kitchen things, sofa, bed, desk, chair, laptop, computer screen, TV, fridge, bathroom, rocket, astronaut, castle, insects...) FIRST search library/models/catalog.txt (e.g. grep -iE 'bus|tram' library/models/catalog.txt) and use it: <KitModel file="<file>" h={<h>} p={[x,0,z]} rotY={...} /> with file, h and any body=/flip from that line (write the file path as a plain string; tools/render.sh copies it into the video). Pick variety from the catalog (several tree or car kinds) rather than repeating one. Lines marked code are objects built for earlier videos: copy library/props/<name>.tsx to <video>/project/custom/_prop_<name>.tsx and import it. ONLY if nothing fits, build the object in code as a reusable prop: <video>/project/custom/_prop_<name>.tsx (name in kebab-case), first line `// prop category=<category> h=<height in m>`, a default-exported component taking { p, rotY, s } and built from the kit shapes; the pipeline saves new props into library/props so the next video reuses them. PEOPLE ON BICYCLES: always the kit's <Cyclist spec={...} p rotY t bike rpm steer /> (a full Toy leaning forward on the saddle, palms fixed on the grips, feet on turning pedals; pedals and legs share one crank angle so they always match). It rides toward its own +z, so set rotY to the direction of travel; pass t (shot time) so it pedals, rpm 0 to coast, and steer (-1 left .. 1 right) while it turns so the hands and head follow the turn. Never put a Mini on a bike: Mini seated is torso-only, for passengers hidden inside vehicles. FACING: every library model is placed so its front points +z; a catalog line marked flip faces backwards in its file, so pass flip (e.g. the Bicycle). A vehicle must face the way it moves. ANIMALS: ready ANIMATED animals first: catalog category animal (alpaca, bull, cow, deer, donkey, fox, horse, white horse, husky, shiba-inu, stag, wolf) are rigged and move by themselves: <AnimatedModel file="models/quaternius/animals/Cow.gltf" h={1.5} clip="Walk" t={t} p={[x, 0, z]} rotY={...} /> with a motion from that line's anim= list (Walk, Gallop, Eating, Idle, Idle_Headlow...). The motion plays in place: to cross the set, move p with t (walk about 1 m/s, gallop about 5 m/s) and set rotY to the direction of travel (front = +z). Any rigged catalog line (anim=...) works the same way, e.g. the space astronauts; KayKit adventurers (category person) are fantasy knights and mages: only for history or fantasy stories, never instead of the cast (people are always the kit's Toy). Insects (category insect) are at real size: give a bigger h for close-ups. For an animal not in the catalog, never hand-build it from loose shapes. Use a preset (`<Quad spec={ANIMALS.horse} pose={{ walk: t }} />`), change it (`{ ...ANIMALS.dog, c: "#222" }`), or write a new spec for its body plan with 1-3 signature features that read as a silhouette (an animal not in the list: nearest body plan + its features, e.g. a zebra = ANIMALS.horse with stripes, a wolf = ANIMALS.dog with pointy ears and a bushy tail). Animal specs go in CAST like people. Put each character's spec in ONE place: export const CAST = {...} at the end of _kit.tsx, copied from cast.json, and import it in every shot.
   BATCHES: a long video is built in several runs, each with its own list of shots. If the task says the 3D world already exists,
   do NOT redo steps 1-2: read characters/cast.json, project/custom/_kit.tsx and one or two finished S*.tsx shots that use the same set,
   then build only the shots in your list with the same cast, the same set pieces (copy the set code, do not redesign it) and the same
   scale and lighting, so batches match. Never rewrite a finished shot. In the first batch, cast.json covers EVERY character in the
   storyboard, not only the ones in your shots.
3. SHOTS: for each shot in the task write `<video>/project/custom/S<scene>_<shot>.tsx` (default export, props { lines, start, duration, accent }): one <Stage> with a set, the cast posed and ACTING what the action says (walk in with walk: t, point with armR, look up with head/tilt/look, reach, nod), with a facial expression that fits the line (expr: joy, laugh, sad, cry, angry, surprised, fear; neutral when calm), head-first turns (...turn(t, keys)), anticipation on big moves (kfA for arm raises and points, ...jump(t, t0) for jumps), lean (bends at the hips), crouch, sit / <Seated>, mouths with talk("<Speaker>", lines, start, t) for anyone speaking on screen, and a gentle camera move with kf (dolly, pan or push-in; never static). Time the key moment to the word in lines.json (start of the shot = `start` seconds). Keep figures inside the middle of the 9:16 frame: labels sit in the top 18%, captions in the bottom 30%; frame so heads are never cut off.
4. CHECK: run `tools/still.sh <video> <seconds> <video>/logs/still-S<scene>_<shot>.png` at the middle of each shot (seconds from timeline.json) and open every still. Fix anything cut off, overlapping, too dark, or off-model (wrong colours = wrong person), then re-check. If a build fails, read the error, fix the file, try again.
Style (brief.json "style"):
- **explainer**: build a DEMONSTRATION, not a scene. The thing being taught is centre frame, large, lit and unobstructed; the
  set is only what is needed to understand it. Use the shot's "claim" and "point": the named thing must be the clearest object
  on screen while that word is spoken. Good tools: a cutaway (hide the front wall so the inside shows), a labelled prop held up
  or placed down, one figure pointing at the thing (not acting a scene), parts that move in the order the line explains them,
  two objects side by side for a comparison, a simple scale or gauge that fills. Keep the camera still or slow: the viewer is
  reading the frame. No crowds, no background business, no dramatic angles.
- **animated**: build a scene: characters acting, a set with life in it, cinematic camera moves.
Rules: frame-driven only (useShotTime, kf); deterministic (rng(seed), never Math.random); smooth Lego V5 look from brief.lookStyle (never flatShading or raw boxGeometry: use Box/Ball/Pill/RoundGeo; tools/smooth3d.py also smooths everything before render); no text inside the 3D scene and no text overlay in the shot (labels and captions are added by the engine, in the top and bottom bands; keep the cast and action in the middle band of the frame); one file per shot plus the kit.
Memory: before you start, read `.claude/agent-memory/set-builder/MEMORY.md` and any topic file it points to.
