# REELIX rules
- Models are used from the AI Video Editor folder through config/models.json. Never copy them or that repo's structure here.
- Skills in .claude/skills are downloaded and used unmodified. If one does not work, replace it with a better one found online (record it in SOURCES.md); never edit it.
- One heavy model at a time (16 GB Mac): FLUX, Kokoro, ACE-Step, Wan run one after another. The ACE-Step music server is closed as soon as the music step ends (even if it was already running) and again before Wan (freeMusic in cli/pipeline.mjs); a leftover server once filled swap and got Wan killed.
- A video is made only by the pipeline (cli/pipeline.mjs); agents write their one output file and nothing else.
- Licences: FLUX schnell, Kokoro, ACE-Step are Apache-2.0. Never use flux-kontext-q4 or edge-tts (non-commercial).
- Agent memory lives in .claude/agent-memory/<agent>/MEMORY.md (committed). Agents read it first; the pipeline's last stage adds 1-3 lessons per video. Keep each file under 60 lines.
- Memory growth (automatic, no human step): when an agent's MEMORY.md nears 60 lines or 5+ lessons share one topic (e.g. FLUX prompts, captions, 3D), move them into a topic file in the same folder (e.g. .claude/agent-memory/storyboard-artist/flux-prompts.md), merge duplicates there, and leave one pointer line in MEMORY.md: `- FLUX prompt fixes: see flux-prompts.md (read when writing image prompts)`. Agents read MEMORY.md first and open a topic file when its pointer applies. This is enforced: after every video the pipeline runs tools/memory_check.py (too long, crowded topic, broken pointer, unlinked topic file) and, if it fails, cli/memory.mjs has the producer split/merge and checks again. Run it by hand any time: node cli/memory.mjs
- Shared assets live in library/ (sfx: generated ones by tools/make_sfx.sh plus 169 recorded Kenney CC0 sounds by tools/sfx_library.py fetch, ids k-..., one index.json for both; templates such as three-hero.tsx). Per-video 3D/motion code goes in <video>/project/custom/, never in the engine.
- `reelix viral-ideas`, `reelix list-ideas` (alias saved-ideas) and `reelix help` are commands, so a video can't be named viral-ideas, list-ideas, saved-ideas, ideas or help. Ideas lists go to ideas/ (not in git).
- Models per agent live in `.claude/models.json` (first model + fallbacks, effort, turn cap; the agent files carry the same model/effort/maxTurns). On a usage/rate limit or overload the pipeline re-runs that agent on the next model. Strongest -> lightest: fable, opus, sonnet, haiku; simple jobs use sonnet to save usage.
- 3D AI motion look (look "aimotion", AI motion V4): each character first gets a hero picture (characters/<name>-hero.png); every shot is then drawn by klein's edit mode WITH those heroes as references, so the same character appears in every shot. A recurring object can do the same: a storyboard shot's "objects" (up to 2 model-library files) are rendered once by tools/object_ref.sh in the heroes step (characters/obj-<name>.png) and given to klein as extra references (shape, parts and colours kept; ~110 s per picture instead of ~42 s; docs/experiments/2026-11-21-kit-ai-references). tools/wan_i2v.py (Wan 2.2 FastWan via AI Video Editor's envs/video, config videoWan, always offline) animates the shots; the text model reads all prompts once per video. Each shot has a speed plan (storyboard "speed": "hurry" | "calm" | "slow" | ramp keys; default 1.25x because Wan's motion is slow); tools/grade.py applies it with tools/speed_ramp.py (motion blur above 1.3x), colour-matches clips (one correction per clip, never per frame; keepLight shots untouched), applies the approved balanced grade and AI-upscales every clip 3x with Real-ESRGAN (config upscale, ~25 s per clip), with no blur and no frame blending (docs/experiments/2026-11-15-wan-sharpness, 2026-11-19-aimotion-v4-speed). Wan is heavy: never run it next to FLUX, Kokoro, ACE-Step or a render.
- 3D Lego look (look "toy3d", Lego V5): library/templates/toy3d-kit.tsx is the shared kit. People breathe, blink and shift weight by themselves and take expr (8 expressions), turn() (head-first turns), kfA() (anticipation), jump(), crouch, sit/<Seated>, child; props use AtHand/AtHead/handWorld, clothes use Apron; animals are the library's animated animals first (AnimatedModel), otherwise made by body plan + spec (Quad, Bird, Fish, Turtle, ready specs in ANIMALS; never loose shapes; docs/experiments/2026-11-21-lego-animals), older Sheep/Duck/Rooster; effects are FireFX/Glow/MoltenRibbon. Soft things are smooth, rigid things keep their shape: tools/smooth3d.py runs on <video>/project/custom before every render (docs/experiments/2026-11-19-lego-v5).
- Looks are offered per style (config/looks.json): each look lists "styles" it belongs to, "best" marks the one recommended for that style, "planned": true hides a look until it is built. Explainer offers the 3D looks (and Chalkboard once built); Animated offers 2D and 3D. The "2D or 3D" question is skipped when a style has only one dimension. Flags (--look) are not restricted; the questions are.
- Length (config/formats.json `<format>.lengths`, brief.json `targetSec` + `length` + `lengthLabel`): a Short is 30, 60, 90 or 120 seconds (only these); a video is standard / long / deep (about 2.5 / 5 / 10 minutes) or its own length in minutes (`--length 7`, 1.5 to 12). cli/common.mjs `lengthFor()` is the one place that reads a length. Everything downstream follows `targetSec`: the script-writer writes targetSec x 2.6 words and researches deeper the longer it is (more sources, every spoken fact confirmed by two sources from 240 s up, research.md grouped by chapter); the storyboard-artist holds shots longer above 180 s; a 30 s Short animates every shot with Wan, anything longer only its "move" shots. Long jobs are split so no agent run is too big: the Lego 3D build goes 12 shots per set-builder run, the picture check 30 frames per run, and music over ~4 minutes is one 3-minute take looped with crossfades. A 30 s Short must behave exactly as before any change here.
- Model library (library/models; docs/experiments/2026-11-21-lego-objects and -img2threejs-objects): everyday objects in the Lego look come from ready-made CC0 kits FIRST (1,572 models: 12 Kenney kits incl. city roads/shops/industry, food, furniture, space, castle; Quaternius models plus its food, space, farm and animated-animal packs; KayKit furniture and adventurers; poly.pizza insects; sources.json "packs"; approved from docs/experiments/2026-11-21-kit-*; catalog library/models/catalog.txt and index.json, made by tools/model_library.py index), loaded with the kit's KitModel (sized in metres, repainted in the Lego satin plastic; rigged files are copied with their skeleton). Catalog lines with anim=... are rigged and move: the kit's AnimatedModel plays one named motion driven by shot time (animals walk, gallop, eat; animals come from here first, body plans only for the rest). Quaternius OBJ packs store Blender-linear colours: fetch converts each .mtl once (sources.json linear). Only a missing object is built, in code, as <video>/project/custom/_prop_<name>.tsx; the render step (saveNewProps in cli/pipeline.mjs) copies new props to library/props and re-indexes, so the next video reuses them. tools/render.sh and still.sh copy every models/... file a shot names into the video's assets (an .obj brings its .mtl, a .gltf the .bin/.png it names). Model files are not in git: sources.json says where each comes from and scripts/setup.sh fetches them (python3 tools/model_library.py fetch). img2threejs was tested and is slower and plainer; use it only by hand for an object no kit has. Every library model faces +z (catalog `flip` = the file faces backwards, e.g. the Bicycle); people on bicycles are the kit's `Cyclist` (a full Toy on the saddle with turning cranks and pedals the bike model lacks; one crank angle drives pedals and legs via leg IK, palms are solved onto the grips, `steer` turns hands and head into a turn; toy arms are short, so it leans ~43 deg and rider legs are 15% longer), never a `Mini` (seated Mini is torso-only, for inside vehicles).
- 2D and Chalkboard assets (approved 2026-11-21, for the Chalkboard look and flat 2D work; fetched by tools/asset_library.py, not in git): library/icons/lucide (1,540 Lucide icons, ISC: keep its LICENSE), library/maps (Natural Earth GeoJSON; tools/map.py draws any region, --chalk for the board look), library/peeps (Open Peeps; tools/peeps.mjs draws a person, art CC0), library/chalk/fonts.json (14 handwriting Google fonts, no download). Rejected: photo sky HDRIs behind toy models (too real, they do not blend). Real paintings: undecided, still an experiment.
- No text over the animation: labels go in the top band (16:9 top ~15%, 9:16 top ~17%), captions in the bottom band (16:9 bottom ~18%, 9:16 bottom ~28%). The engine (templates/remotion/src/Main.tsx TopTags) draws the scene label and the storyboard shot "label" (timeline note) in the top band; shots never draw their own label overlays. 3D sets keep the cast in the middle band.
- Captions on the video are OFF by default: brief.json `captions` (true only with `reelix --captions`, or Captions On in FE-Reelix) becomes timeline.json `showCaptions`; templates/remotion/src/Main.tsx draws them only then. The whisper step still runs, because captions.json word times are used for timing (sfx, fixes). When shown they sit in the bottom band the shots keep free (video 16:9: bottom 56 px, 60 px words; short 9:16: bottom 340 px, 84 px words), never mid-frame over the action (docs/experiments/2026-11-21-caption-place). Reviewer and animator skip caption checks when it is off.
- The pipeline keeps the Mac awake by itself: cli/pipeline.mjs starts `caffeinate -dims -w <its own pid>` first thing, so every way of making a video (terminal, ideas list, FE-Reelix, a continued run) stays awake until it finishes or stops, and no `caffeinate reelix ...` is needed. It cannot stop a closed lid from sleeping the Mac. Never remove it: a sleeping Mac pauses a run for hours.
- Usage limits never fail a run by themselves: an agent that hits a limit is re-run on the next model (.claude/models.json), and when EVERY model is limited and the message says when it ends ("resets 1:30am"), cli/pipeline.mjs waits for that time (+2 minutes) and tries again, up to 4 times per agent run, keeping the Mac awake. Only a limit with no reset time, or one more than 6 hours away, stops the run. While it waits, the step is marked paused: its percent stands still and the time left shows the work still to do plus the wait, so waiting never looks like progress. cli/common.mjs LIMIT_RE (what counts as a limit) and limitReset() (when it ends) are the two places to update when the CLI words a limit differently.
- Every tool runs OFFLINE: tools/common.py sets HF_HUB_OFFLINE / TRANSFORMERS_OFFLINE (wan_i2v.py sets its own, it does not import common). All models are already on this Mac, and a hung network check once made the voice step take an hour instead of a minute. Never remove this; set the vars to 0 by hand if you really need a download.
- Experiments and tests: each in its own folder docs/experiments/<yyyy-mm-dd>-<short-name>/ (never loose files) with a STATS.md: why we tested, what was tested and the result, old way vs new way, every file with what it is, what it was built with and the verdict, the numbers, and the conclusion (what we shifted to). Example: docs/experiments/2026-11-15-wan-ai-motion/STATS.md. The whole docs/experiments folder is local only (in .gitignore, never in git: it is no use to someone who clones and too big); every experiment still keeps the scripts that re-make its pictures and videos. Nothing from an experiment goes into SETUP.md or README.md until the user approves it for the main pipeline.
